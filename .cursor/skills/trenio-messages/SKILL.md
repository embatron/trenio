# Direct messages

Read `.cursor/rules/messages.mdc` first. Product copy and limits are in `docs/TECH_SPEC.md` §4.6. This skill is the edit map.

## Files

| Concern | Location |
| --- | --- |
| Tables | `src/db/schema/messages.ts`. Apply attachment SQL with `npm run messages:install`, not `db:push` |
| File rules and storage | `src/lib/messages/attachments.ts`, `src/lib/messages/attachment-store.ts`, `src/lib/messages/file-download.ts`. An image `sharp` cannot decode is refused and removed from disk |
| Account deletion | Deleting the account removes that person's threads for both sides, their bookmarks, and other people's bookmarks of their card. Likes stay and read as a deleted account. The six-month hold only keeps the login and the card so they can be restored |
| Access, send, read cursor, unread SQL | `src/lib/messages/service.ts` |
| Zod and preview | `src/lib/messages/schemas.ts` |
| Server functions | `src/lib/messages/functions.ts` |
| Live socket | `server/routes/messages/live.ts`, `src/lib/messages/live-hub.ts`, `src/lib/messages/live-client.ts`. A `cabinet` frame asks the open pages to pull likes, favorites, statistics, and the cabinet counters. It carries no counts |
| Socket fallback | `src/lib/messages/polling.ts` (`MESSAGE_SOCKET_FALLBACK_MS`). Trainer, user, and admin cabinet counters use the cabinet pull, not a second timer |
| Email and Telegram debounce | `src/lib/messages/notify.ts` |
| HTML allow-list and grapheme length | `src/lib/catalog/review-html.ts` |
| Emoji picker | `src/components/messages/emoji-panel.tsx` (`emoji-picker-react`, Russian data, skin tones, the full set) |
| Composer, editor, bubbles, live unread | `src/components/messages/` |
| Header count | `MessageCount` in `src/components/site-chrome.tsx` |
| Routes | `src/routes/account.messages*.tsx`, `me.messages*.tsx`, `admin.messages.tsx` |

Do not import `src/db/` or `src/auth/` from those client components. Do not hand-edit `src/routeTree.gen.ts`.

## Logging

Message mutations log `domain: "message"` through `writeLog` in `src/lib/messages/functions.ts`. Store the conversation id in `target` and the visible length in `chars`. Do not write the HTML body, the preview, or the notification text into `app_logs`. List, thread, read, and unread polls log only failures. See `.cursor/rules/logging.mdc`.

## Access

1. Resolve the published profile by slug. Unpublished or missing profiles cannot be messaged.
2. Open the existing dialog of this account with this card, including a closed one. If that card has no row yet, reuse the dialog those two accounts already share, including the portal welcome (`host_user_id`, no card). If none exists, create the one `open` row for `(user_id, trainer_profile_id)`. A second open card row hits the partial unique index. An empty duplicate of the same pair is deleted. The clicked card's own row wins over a busier dialog with someone else.
3. `assertConversationAccess` decides read, write, close, reopen, block. Staff may read any thread. Staff write only when they are the initiator or the owner. The welcome thread is with the admin user `trenioby` (`conversations.host_user_id`). It has no trainer profile, so the name is not a link to `/trainers/trenioby`. The database rejects a trainer slug `trenioby`. Do not create that card. The letter body is the `trainer_welcome` row, edited at `/admin/site`.
4. `sendMessage` is idempotent on `(conversation_id, client_id)` via `ON CONFLICT DO NOTHING`.
5. `consumeRateLimit` still caps sends: 10 per minute and 300 per day. A separate durable check allows one user to message at most 10 distinct trainer profiles per Europe/Minsk calendar day. A repeat to a trainer already messaged that day is allowed. The profile owner's replies are not counted. The 11th trainer is refused with `DAILY_TRAINER_LIMIT_MESSAGE`, and the cabinet shows that text in `CabinetNotice`.

## Send path

1. `messageMarkup` turns the field into HTML, then `sanitizeReviewHtml` checks the length. Tags are `b`, `strong`, `i`, `em`, `u`, `s`, `code`, `pre`, a spoiler `span`, `ul`, `ol`, `li`, `p`, `br`, and safe `a`. The screen does not explain how the styles are typed.
2. `reviewTextLength` counts graphemes. First message from the initiator: `FIRST_MESSAGE_MAX_LENGTH` (1000). Every later message: `MESSAGE_MAX_LENGTH` (4000). Stored HTML: `MESSAGE_HTML_MAX_LENGTH` (12000). Attachments do not count toward that limit. An empty body is stored only when at least one attachment is linked. Format characters alone, such as zero-width spaces, are empty. `sendMessage` awaits `assertSendRate` before the insert. A client id that is not a uuid is refused before the query.
3. Enter sends `composerBody(editor.innerHTML, state)`. The visible field wins when React state is still empty. The caret stays in the field. Ctrl+V or ⌘V pastes a screenshot as an attachment, not as a picture inside the text. A picture over 5 MB is reduced until it fits. Shift+Enter inserts one line break. Runs collapse to one blank line and the draft keeps at most 200 breaks. Ctrl+Enter and ⌘+Enter still send. A repeated Enter does not send again while the first send is in flight.
4. Insert and set `last_message_at` in one transaction. A participant may clear the thread for themselves (`message.clear`). The other side keeps every message and sees «Переписка была удалена пользователем» only when a message from before that clear is still visible. An empty open-then-delete leaves the other account's list untouched. Until a message exists, only the opener sees the row. Opening the same person again restores that account's empty draft without the old text. A newer message brings the cleared copy back. The row is removed for both sides only when an account is deleted.
5. A reply may set `reply_to_id` to a message in the same conversation. The control is a reply arrow beside the bubble. The quote in the bubble and the bar above the field are one short muted line with a left stroke. The quote does not widen the bubble. The quoted message uses a slightly deeper bubble color. The sender edits from a pencil icon for 15 minutes (`message.edit`, `edited_at`). An edit does not move `last_message_at` and does not send another notice. The list search matches a name or message text from two characters and is not logged. A given name or surname still matches through `messagePersonMatches`: a Latin keyboard, mixed lookalike letters, a skipped space, or one swapped, extra, or missing letter.
6. Notify the other party through `scheduleMessageNotification`. Mail and Telegram wait two quiet minutes, then only go out when that person is offline. While they are on the site or were here within ten minutes, the letter waits another minute and checks again. The wait is a row in `message_notices` (`npm run messages:install`), so a restart still sends it. One update moves `due_at` forward and sends; a second worker sees the later time and leaves the row. The browser push waits 15 seconds, then waits with the letter until that person is offline. The HTML letter includes the sender name, a circular portrait, and the message text, and only when that mailbox is verified (`email_verified_at`) and «Сообщения» is on. A pending signup address is skipped. Telegram stays a short note without the text, with a button that opens the thread in the Mini App on https. It goes to either participant when `telegram_user_id` and `telegram_bot_seen_at` are set, and only when they are offline. A computer, a phone, or the installed app gets the same short note as a system push (`public/sw.js`, VAPID) while `users.push_messages` is on. That switch defaults to on. The cabinet row «В браузере» turns it off and deletes subscriptions. The browser permission is requested on the first tap, not from a custom banner. A focused tab skips the system banner; the open page shows «Вам написали» with the sender name and «Открыть». Skip when `last_read_message_id` already covers this id. Do not write the message text into `app_logs`.

## Receipts and unread

- The message letter is skipped when the mailbox is not verified or the recipient turned off «Сообщения» in settings (`users.mail_messages`). Telegram still sends to a participant who already opened the bot or the Mini App. A browser gets a system push while «В браузере» is on (`users.push_messages`, default true). Staff report mail is not part of that switch.
- `conversation_reads.last_read_message_id` is a bigint with no foreign key.
- For the sender, the other reader is the profile owner when the viewer is the initiator, and the initiator when the viewer is the owner. No owner means the receipt stays `delivered`.
- `receipt` is `read` when that cursor is greater than or equal to the message id, otherwise `delivered`. The bubble copy is «Прочитано» or «Доставлено». Pending client sends show «Отправка…». The conversation list uses the same pair for the latest message: one check in the right corner means delivered, two checks mean the addressee has read it. An unowned profile stays one check. Every role uses that list.
- `unreadSummary` is one SQL: `{ own, inbox, total, ownedSlugs }`. `own` and `inbox` count messages someone else sent to this account that this account has not opened. A message this account sent is excluded. Root `beforeLoad` loads it. `MessagesLive` keeps one websocket at `/messages/live` and refreshes that summary when an unread event arrives. While the socket is down it refreshes every 20 seconds. Typing («печатает…») goes only to the other participant and is not logged.
- Opening a thread does not mark the newest id by itself. `markConversationRead` advances to the latest message whose bottom edge has entered the visible log, on a phone, a tablet, and a wide screen. A message that still hangs below that edge stays unread until the reader scrolls its end into view. The same rule marks a portal welcome in the admin cabinet: the host is a participant (`canMarkRead`) even though that thread cannot be reported. A staff reader who is not in the thread does not move the cursor. That open is `message.staff.read`, and the staff inbox is `message.staff.list`: one journal row per actor and thread every 30 minutes, with no message body and no search text. Participant polls stay failure-only. The header, the menu, and the dialog row drop that count when the cursor moves.
- A reply advances the same cursor to the new message before the list reloads. Every incoming message up to that reply is read, and the same three counts drop. The list must not reload the old unread number ahead of that cursor.
- On open, pin the log to the bottom when the unread tail fits. When it is taller than the pane, scroll to the top of the oldest unread message (`viewerReadMessageId` from that first payload) so a long message starts at its first line. A message the viewer just sent still pins to the bottom. Someone who is not a participant stays at the bottom.

## UI

- The write mark is `DirectMark` (one outline plane). On a contact row it sits in a coral rounded square the same size as Instagram. The plane stays inside that square. Hover moves it. A click by someone other than the owner is a `message` contact click. The inbox mark is `MESSAGE_ENVELOPE`. Catalog cards do not show the plane.
- The trainer cabinet sidebar and the plain-user account sidebar both say «Мои сообщения». The admin nav label stays «Сообщения». The conversation list has no «Сообщения» heading. The header envelope stays «Сообщения». When a trainer, a club, or a plain user has unread messages, the burger and the nickname in the site menu show a very small brand-colored exclamation mark. Staff do not. On a phone the site menu lists the same sections as that cabinet's sidebar, in that order, with the same counts and the same line icons. The header profile mark is only a link to the cabinet home. Favorites, reviews, likes, bookings, and nested cabinet counts stay muted. The messages number is the brand color when it is not zero. For every role the envelope, the site menu, and the cabinet sidebar share one unread total (`own + inbox`): messages someone else sent to this account that this account has not opened, including threads the trainer started. A message this account sent stays out of that total. On the staff list a row badge counts the same incoming unread, and only when this account is a participant. «Переписки (N)» stays the number of conversations. The new-report count stays on «Жалобы (N)».
- Each dialog row and the open thread show the other person's presence: a green dot is on the site (a visible tab in the last minute), an orange dot is away (the tab is hidden, they switched browser, or they were here within ten minutes), and a gray dot is offline. Mail, Telegram, and the browser push wait until the gray dot. The list refreshes that dot about every 30 seconds while the page is visible.
- The conversation list is newest activity first. On a wide screen, the first visit to `/account/messages` and `/me/messages` with no id replaces the URL with the first row. After the X hides the thread, the page stays on the list until a row is chosen. On a phone, stay on the list until a row is opened; the thread then fills the screen under the header, and «К списку» returns to the list. The phone's own back button returns to that list as well; the next press leaves the messages page. A dialog opened from a profile, a notification, or a fresh tab keeps the list behind it, and `?trainer=` is pushed on a phone so the list stays in history. Hover tints the row and turns the name brand-colored. A `?trainer=` link resolves that card's existing dialog, or creates it, and opens that id. The newest row is not substituted while that lookup is in flight. The trainer list includes threads the trainer started.
- Image bubbles use `/messages/files/{id}?preview=1` (a stored JPEG, at most 640px inside) as a 72px thumbnail. The tap target opens the original on the same page and can rotate it by 90 degrees. Documents stay named links. While a send is in flight, a local image uses its object URL in the same frame.
- Client bubbles are turquoise (`is-user`). Trainer bubbles are coral (`is-trainer`). `mine` only places the bubble on the right.
- A participant files one report for the whole conversation from «…» in the thread header, then «Пожаловаться». The dialog asks for a reason and a comment. `reportMessage` writes `conversation_id`, `reporter_side` (`client` or `trainer`), the Russian reason, and the plain comment, and leaves `message_id` empty. A second report from the same person is a duplicate, not a new row. `notifyStaffAboutReport` mails active admins. Do not put the comment in `app_logs`; log `commentLength` only. «Заблокировать» is the next menu item and asks for confirmation. «Удалить диалог» is the item after it and asks for confirmation. `deleteConversationForViewer` stamps `conversations.user_deleted_at` or `conversations.peer_deleted_at` and clears that side's revive stamp. An empty thread stays off the other account's list. Opening the person again stamps `user_revived_at` or `peer_revived_at`. Apply those columns with `npm run messages:install`. `blockPair` writes `blocked_pairs` for the client account and that trainer profile, then closes that one conversation. A portal welcome is a thread with the admin: report, block, and delete are hidden and refused. Either participant stops. The account stays active. Dialogs with other trainers stay open. `unblockPair` removes that row and opens the thread again. The control is a button in the middle of the blocked thread, after a confirmation. The composer placeholder «Написать сообщение» is an overlay, not field text.
- In the list and the thread header the given name and surname stay on one line. Do not show «Открыта» or «Закрыта» next to the name. A closed thread is explained in the composer. The composer text is 14px on a wide screen and 16px on a phone, so the keyboard does not zoom the page.
- The portrait is the published card photo when that account has one, otherwise the account photo. A published name opens `/trainers/{slug}` in a new tab and uses the same new-tab mark as the cabinet identity. A plain account name stays text. When the header shows the client, «Тренер: …» opens that thread's card in a new tab with the same mark.
- On a phone the thread slides in under the header on a white sheet. The top edge stays under the header. New bubbles, the typing line, the quote bar, and the menu ease in. Reduced motion turns those fades off. The pane itself does not jump. The phone layout comes from the width, so it does not wait for a class and then jump. «К списку», a swipe from the left edge, and the phone's own back button return to the list. The next phone back leaves the messages page. There are no previous or next arrows in that header: they covered the name, and the next thread is opened from the list. A wide screen still shows those arrows. The composer rises above the keyboard. Block and report stay in the «…» menu.
- On a wide screen the X hides the open thread. It does not mark the conversation closed and does not show «Открыть». The row stays in the list. The page does not open the first row again after that.
- The header envelope goes to `/me/messages` for a trainer or club and shows the same incoming unread total as «Мои сообщения» (`own + inbox`). Staff go to `/admin/messages` and use that same incoming total. A row badge counts incoming unread only when this account is a participant. «Переписки (N)» stays the number of conversations. Everyone else goes to `/account/messages`, and that cabinet badge counts unread in the threads that page lists. `/admin/messages` opens on «Переписки (N)» (every conversation). «Жалобы (N)» is the second tab.
- `MessageEditor` is one contenteditable field. Emoji are inserted as a text node and an `input` event. Do not rely on `document.execCommand`.
- The emoji button opens `emoji-picker-react` above the field. It is not a toolbar.
- Catalog trainer cards do not render `TrainerContactIcons`. After the bookmark, `CardDirectLink` opens the same thread in a new tab. The city, sports, price, and rating stay, and the given name and surname stay fully visible. On a trainer profile the same icons sit after reviews under «Как со мной связаться». The phone is a handset and a `tel:` link; the profile row also shows the number. There is no email icon. Telegram uses `TelegramIcon` from `src/components/brand-icons.tsx`. Direct opens `/me/messages?trainer={slug}` for a trainer or club, `/admin/messages?trainer={slug}` for staff (the «Переписки» tab with that dialog, not `/admin`), and `/account/messages?trainer={slug}` for a client, in a new tab. A guest still lands on login and returns to the client thread; after login a trainer or club goes to `/me/messages` and staff go to `/admin/messages`, keeping the trainer.
- `.layout-staff` wraps only `src/routes/admin.tsx`.

## Changing the schema

`npm run db:push` is not safe here: the database enum `otp_purpose` does not match Drizzle. Apply a narrow `ALTER` for message tables. Do not drop `otp_purpose`.

## After a behavior change

Update `docs/TECH_SPEC.md` §4.6 and, if routes changed, `docs/README.md`. Keep this skill and `.cursor/rules/messages.mdc` in sync with the code. UI strings stay Russian.
