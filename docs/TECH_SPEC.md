# Trenio.by — техническая спецификация

Единый инженерный документ проекта. Продуктовый контекст — [PRODUCT.md](./PRODUCT.md), доменная модель — [ACCOUNT_MODEL.md](./ACCOUNT_MODEL.md).

**Домен:** trenio.by · **Рынок:** Беларусь · **MVP:** каталог тренеров и клубов, конверсия через контактный клик.

---

## 1. Архитектура

```
Browser / PWA client
        │
        ▼
TanStack Start (SSR + client hydration)
        │
        ├── File routes (src/routes/*.tsx)
        ├── Server functions (src/lib/auth/functions.ts, …)
        └── Middleware (src/start.ts, src/auth/middleware.ts)
        │
        ▼
PostgreSQL (Drizzle ORM, src/db/)
```

| Слой           | Технология                           | Путь                                                |
| -------------- | ------------------------------------ | --------------------------------------------------- |
| Framework      | TanStack Start + TanStack Router     | `src/routes/`, `src/router.tsx`                     |
| UI             | React 19, Tailwind CSS v4, shadcn/ui | `src/components/ui/`                                |
| Site UI        | Кастомные компоненты каталога        | `src/components/site-chrome.tsx`, `auth-styles.tsx` |
| SSR entry      | Nitro / Cloudflare preset (Lovable)  | `src/server.ts`, `vite.config.ts`                   |
| Start instance | Request middleware                   | `src/start.ts`                                      |
| Auth (server)  | Sessions, password, RBAC             | `src/auth/`                                         |
| Auth (RPC)     | `createServerFn`                     | `src/lib/auth/functions.ts`                         |
| DB             | Drizzle + postgres.js                | `src/db/`                                           |
| Hooks / utils  | Shared client helpers                | `src/lib/`, `src/hooks/`                            |

**Node.js:** >= 22.12 (TanStack Start). **Package manager:** npm (есть `bun.lock`, но npm — основной для CI/seed).

## 3. Маршрутизация

File-based TanStack Router: `src/routes/<name>.tsx` → URL.

| Паттерн              | Пример                             |
| -------------------- | ---------------------------------- |
| `index.tsx`          | `/`                                |
| `search.tsx`         | `/search`                          |
| `trainers.$slug.tsx` | `/trainers/:slug`                  |
| `auth.login.tsx`     | `/auth/login`                      |
| `__root.tsx`         | App shell, session in `beforeLoad` |

Root context: `{ queryClient, user: PublicUser | null }` — сессия через `getSessionFn`. У вошедшего в шапке стоит его аватар: фото аккаунта, а у тренера и клуба — первое фото профиля. Рядом с аватаром у тренера и клуба виден ник (Instagram или адрес профиля). У обычного пользователя ника в шапке нет. На узком экране, где поиск в шапке скрыт, остаётся только аватар. Он ведёт в кабинет. Список кабинета открывается в меню сайта: аватар и ник, под ними тот же набор пунктов. Города — отдельный пункт «Города», список открывается под ним.

### Город посетителя

На страницах категории (`/categories/yoga` и вложенные) город в фильтре подставляется сам, если IP удалось сопоставить с населённым пунктом Беларуси. Библиотека — [`ip-location-api`](https://www.npmjs.com/package/ip-location-api) с бесплатной базой GeoLite2 City (язык `ru`, режим `smallMemory`). База лежит в `data/geoip/` и не коммитится. Перед выкладкой: `npm run geoip:update`.

IP берётся из `CF-Connecting-IP` или `X-Real-IP`. Если в запросе только локальный адрес (так у `trenio.local` за Apache), браузер один раз узнаёт свой публичный IP и сервер ищет его в той же базе. Город подставляется только когда это населённый пункт Беларуси. Результат и ручной выбор пишутся в cookie `trenio_place` на год. «Сбросить» очищает город и больше не подставляет его, пока посетитель не выберет населённый пункт снова. IP в cookie не хранится. В базе те же поля, что просит `ILA_FIELDS`: страна, город, радиус и координаты. Координаты нужны странице `/map`, чтобы открыть карту у точки IP. Если страна IP не Беларусь или точку найти не удалось, карта открывается на Минске. В cookie координаты не пишутся.

Поиск на главной, в шапке, на страницах 403 и 404 и при пустой выдаче — одна форма `CatalogSearchForm`. Виды спорта берутся из таксономии (`src/lib/catalog/sport-taxonomy.ts`). Город в поле — определённый или сохранённый населённый пункт, иначе «Минск». Тот же город выбран в фильтре категории; в шапке категории поиск заранее заполнен названием вида спорта.

База GeoLite2 создана MaxMind и доступна на [maxmind.com](https://www.maxmind.com).

Текст закрепа Instagram в эти фразы не копируется: из него берутся поля — вид спорта, стаж, с кем работает, адрес, город, телефон и остальные контакты. Профиль Threads читается по шапке, биографии и постам, пока в них есть факты о человеке. Адрес сохраняется строкой без координат. Синхронизация вызывает тот же геокодер, что и кабинет, и пишет точку на карту карточки. Название зала в адрес не подставляется. Если ни адрес, ни город не названы, импорт записывает город «Минск», и крошки ведут на тренеров в Минске. Лицо — фото профиля, если на нём узнаваем человек. Если это логотип или кадр обрезает лицо, лицом становится ясный портрет из поста. Галерея — два или три кадра, где человек и занятие читаются с первого взгляда. Размер файла только отсекает превью меньше 400 пикселей по стороне: более крупный снимок сам по себе не побеждает. Ещё снимки — из закрепов, других постов и Threads, всего не больше девяти. Снимок с подписью «диплом», «сертификат» или «удостоверение» сохраняется как документ, а не как фото профиля. Поле телефона карточки хранится в виде `+375 29 123-45-67`. На публичной странице номер скрыт, пока владелец не подтвердит его SMS. Импорт без согласия остаётся черновиком («на модерации»). Род определяется при импорте по имени и хранится в карточке отдельно от формы. Привязка здоровается этим именем и выбирает «был» или «была». Адрес страницы и ник равны Instagram (`/trainers/{handle}`), старые именные адреса перенаправляются. До трёх мест тренировок в Беларуси лежит в `training_places`. Первое место дублируется в `address`, `address_lat`, `address_lng`, `geocode_status`, см. §4.7. Ссылка `/trainers/claim/{token}` на странице редактирования не показывается. После публикации или привязки тот же URL открывает публичный профиль. Привязка — после оферты, ника, почты и пароля: аккаунт сразу активен, тренер попадает на редактирование карточки. Ник уникален и не редактируется, смена только через поддержку. Сложность пароля показывается при вводе. Карточка профиля выезжает при первом открытии. В каталог карточка попадает только после публикации. Конверт в таблице `/admin/trainers` копирует текст для Instagram и пишет время в `invite_sent_at`: одна короткая ссылка и только те поля, которых нет в карточке. Первый успешный заход по `/hi/{code}` пишет время в `door_entered_at` и больше его не сбрасывает. В таблице `/admin/trainers` колонка «Заход» показывает галочку с датой или крестик. Код лежит в `preview_token` и открывает `/hi/{code}`: страница как у посетителя, без форм сверху. Окно почты есть только у этой короткой ссылки. Ссылка из письма открывает кабинет, там пароль, затем письмо «Поздравляем»: аккаунт создан, дальше работаем вместе. После публикации конверт не копирует текст. Ссылка действует, пока статус не «опубликован», затем открывает `/trainers/{slug}`. Администратор видит неопубликованный профиль и может поставить любой статус. Тренер меняет публикацию сам: в настройках профиля при входе статус по умолчанию «опубликован», его можно сменить на «скрыт» |

### 4.3 Server functions

Все мутации и приватные данные — через `createServerFn` в `src/lib/auth/functions.ts`:

- `getSessionFn`, `loginFn`, `signupFn`, `logoutFn`
- `requestSmsLoginFn`, `confirmSmsLoginFn`
- `requestSmsSignupFn`, `confirmSmsSignupFn`, `signupWithTelegramFn`, `signupWithTelegramWebAppFn`, `completeSignupCredentialsFn`
- `loginWithTelegramFn`, `loginWithTelegramWebAppFn`, `getTelegramLoginConfigFn`
- `forgotPasswordFn`, `requestPasswordResetSmsFn`, `confirmPasswordResetSmsFn`
- `resetPasswordFn`, `verifyEmailFn`, `updateProfileFn` — имя и фамилия текущего аккаунта двумя полями; `setAccountAvatarFn` — фото в `public/avatars/`. Каталог создаётся с правами 755, иначе nginx не читает файл и кружок остаётся пустым. После сохранения кружок в форме, в шапке и в боковой карточке кабинета меняется сразу, без перезагрузки страницы. На сервере `/avatars/`, `/trainers/admin/` и `/trainers/self/` отдаёт nginx из `public/`, а не снимок сборки
- `changePasswordFn` — смена пароля из кабинета. Текущий пароль нужен, только если `password_set_at` уже заполнен. Иначе человек задаёт пароль впервые, в том числе после входа через Google. Текущая сессия сохраняется
- `requestAccountEmailCodeFn`, `confirmAccountEmailCodeFn` — смена почты кодом из письма
- `requestAccountPhoneCodeFn`, `confirmAccountPhoneCodeFn` — привязка телефона SMS-кодом. Подтверждённый номер записывается и в карточку тренера, если она есть
- `listTrainerReviewsFn`, `createTrainerReviewFn` — отзывы профиля тренера; создание только с сессией (`requireAuthMiddleware`). Новый отзыв уходит на модерацию
- `setTrainerReviewStatusFn` — публикация или отклонение отзыва, только `admin` и `superadmin`. Отклонение требует комментарий клиенту и шлёт ему письмо
- `listTrainerRatingSummariesFn` — средняя оценка и число опубликованных отзывов по тренерам для карточек каталога
- `listCatalogTrainersFn` — опубликованные профили для главной, города и раздела. Черновик, скрытая и архивная карточка не входят. На карточке каталога телефон, Instagram, Telegram и сообщение не показываются. Эти иконки остаются в профиле и проходят те же проверки. Иконки почты нет. Ошибка чтения пишется как `catalog.list`, успех не пишется
- `listFavoritesFn`, `toggleFavoriteFn`, `favoriteTrainerFacesFn` — избранное только с сессией, без срока хранения. Сердечко пишет опубликованную карточку из базы. Список и переключение вызываются с клиента после отрисовки, без перезагрузки страницы. Гость уходит на вход. Счётчик в шапке виден вошедшему пользователю и ведёт в избранное его кабинета: `/account/favorites` или `/me/favorites`
- `getAdminShellFn`, `getAdminOverviewFn`, `getAdminTrainersFn`, `saveAdminTrainerFn`, `getAdminTrainerDetailFn`, `saveAdminTrainerPhotoFn`, `getAdminReviewsFn`, `getAdminAccountsFn`, `getAdminFinanceFn`, `getAdminSettingsFn` — отдельные серверные функции разделов `/admin/*` для `admin` и `superadmin`. Виды спорта — не больше четырёх категорий второго уровня. Город выбирается из населённых пунктов Беларуси. Стаж необязателен: пустое поле хранится как 0 и на карточке не показывается. Цена — целое число или пустое поле: пустое сохраняется как null, на карточке «договорная». Кнопка «Редактировать» в списке открывает карточку во всплывающем окне: крестик, фон, Escape и «К списку» закрывают его, а «Сохранить» и «К списку» стоят внизу окна. Адрес `/admin/trainers/$slug` открывает ту же карточку на странице. В кабинете тренера телефон, Instagram, Telegram и почта стоят в блоке «Что уже есть» на общей панели и на `/me/contacts`. В кабинете тренера отдельного заголовка нет: «Как меня представить» — обязательный текст блока «Обо мне». У сотрудника имя и заголовок в одной строке, город отдельным полем, стаж выше контактов, Instagram и Telegram внизу, формат занятий и аудитория из таксономии, до девяти фото. Телефон карточки равен телефону привязанного аккаунта и подтверждается SMS. Входы, логи и прочие данные видит только сотрудник. «О себе» и «Как проходят мои тренировки» — тот же короткий редактор, что у отзыва: жирный, курсив, списки. Фото можно перетащить: первое становится главным. При сохранении фото сервер пишет оригинал до 1600 px и производные `s128`, `c320`, `c640`, `w960` рядом с ним, без увеличения и без метаданных. Карточки, поиск, профиль и аватары запрашивают производный файл и возвращаются к оригиналу, если его ещё нет. Файлы лежат в `public/trainers/` и `public/avatars/`. Dev-сервер отдаёт их с диска, не дожидаясь перезапуска. Оболочка кабинета одна, у пользователя и тренера свои маршруты: `/account/*` и `/me/*`. Имя тренера редактируется в настройках и копируется в карточку
- `getUserCabinetFn` — свои отзывы, телефон и статус телефона. Кабинет: `/account/reviews`, `/account/messages`, `/account/bookings`, `/account/favorites`, `/account/settings`. Внизу настроек (`/account/settings` и `/me/settings`) ссылка «Удалить аккаунт» просит пароль и вызывает `deleteAccountFn`: статус `deleted` на шесть месяцев, карточка скрыта, данные на месте. Вход по прежней почте вызывает `restoreAccountFn`. Служебные роли эту ссылку не видят
- Переписка — `src/lib/messages/functions.ts`, все вызовы `POST` и `requireAuthMiddleware`. См. §4.6
- `submitTrainerWelcomeFn` — публичная заявка с `/join/trainer`, `POST`, без сессии. Пишет строку в `trainer_welcomes`: Instagram, Telegram и мобильный РБ. Ссылка «У меня нет Instagram» принимает Telegram или телефон. Та же заявка уходит служебным письмом на `trenioby@gmail.com` с темой заявки со страницы «Стать тренером». Текст письма в журнал не пишется. Если почта письмо не приняла, строка не создаётся и форма просит повторить. Лимит по `X-Real-IP`. Когда тренер открывает черновик по `/trainers/claim/{token}`, `getTrainerClaimFn` ставит `link_sent_at` у заявки с тем же контактом. Первое открытие не перезаписывается. Сотрудник читает строки в `/admin/welcomes` (`getAdminWelcomesFn`). На `/admin/welcomes` контакты стоят столбиком с иконками. Рядом имя карточки, если Instagram, Telegram или телефон совпали. Статус — как у отзыва: «Опубликован», если карточка уже в каталоге, иначе «Новая», «Черновик», «Разобрана» или «Отклонена». Галочка ставит `done` (`setAdminWelcomeStatusFn`). Счётчик в меню — заявки `new`, у которых нет опубликованной карточки. Его отдаёт `getAdminShellFn`
- `getHomeStatsFn` — блок «в цифрах» на главной: число профилей тренеров кроме архива, виды спорта и города из `trainer_profiles`, средний стаж в годах. Подпись склоняется по числу: 1 тренер, 2 тренера, 5 тренеров; так же вид спорта, город Беларуси и год среднего стажа. Когда блок попадает в экран, числа сами считают от нуля до итога, и подпись идёт за текущим числом. Щелчок или Enter считает снова. При отказе от анимации сразу виден итог. В среднее входят только карточки, где стаж указан (от 1)
- `getOwnTrainerProfileFn`, `saveOwnTrainerProfileFn`, `setOwnTrainerPageStatusFn` — карточка тренера для ролей trainer и club. Статус страницы меняется на общей панели, под контактами: опубликована, скрыта или снята с публикации, после окна «Сохранить». В каталоге видна только опубликованная. Форма «Мой профиль» начинается с ника, затем фото. Смена ника — письмо на trenioby@gmail.com с темой [SUPPORT REQUEST]. Если почта письмо не приняла, форма говорит об этом и не пишет успех. Имя и фамилия берутся из аккаунта: форма профиля их не показывает и `users` не перезаписывает. Сохранение до трёх адресов геокодирует текст, если координаты ещё не подтверждены. Адрес вне Беларуси отклоняется. См. §4.7
- `getPublicTrainerContactsFn` — контакты публичного профиля. Телефон отдаётся только после SMS или после подписанного контакта Telegram. Telegram — только при `telegram_verified_at`. Почта входа на публичной карточке не показывается. Instagram виден по ссылке или, у импортированного профиля, по нику. В «Что уже есть» на `/me` пустые телефон и Telegram можно добавить. Номер из Telegram пишется только если подпись контакта сходится с тем же Telegram-пользователем. Подтверждённый другой номер не заменяется. Запрос только телефона не пишет Telegram
- `requestAccountEmailCodeFn`, `confirmAccountEmailCodeFn` — один код на почту входа. Подтверждение пишет адрес в `users` и ту же почту в карточку тренера. Общая панель и настройки вызывают этот код; отдельные функции почты карточки делают то же самое
- Ссылка «Стать тренером» в настройках обычного аккаунта ведёт на `/join/trainer`, ту же форму Instagram. Тренер, клуб и сотрудник её не видят
- `recordTrainerProfileViewFn`, `getOwnTrainerViewStatsFn` — запись и сводка посещений профиля, чужих сохранений этой карточки по дате добавления и показов карточки. Свой список избранного и сохранение владельцем в сводку не входят. См. `trainer_profile_views` и `trainer_card_impressions`
- `recordTrainerCardImpressionsFn` — пачка показов карточек, которые посетитель увидел в каталоге. Ошибки пишутся в журнал, успех не пишется
- `suggestAddress` — подсказки адреса только по Беларуси и на русском, `POST`, `requireAuthMiddleware`, не чаще одного запроса в секунду на пользователя. Запрос асинхронный. Ответ — `{ suggestions, unavailable }`, в подсказке `{ displayName, city, district, street, lat, lng }`, без сырых полей Nominatim. `unavailable: true` — временная ошибка, а не «адрес не найден»
- `getTrainerAddressFn` — публичные места карточки для `/trainers/$slug`: город, район, адрес и координаты, координаты только если статус `ok`
- `listMapAreaFn` — один кадр публичной карты `/map`. В браузер не уходит весь каталог: в ответе группы точек или отдельные метки этого кадра и одна страница ближайших к его центру тренеров. Только опубликованные профили и места со статусом `ok`. Без телефона и почты. Черновик и адрес без точки не попадают в ответ
- `adminGeocodeTrainer` — повторное геокодирование сохранённых мест, `POST`, только `admin` и `superadmin`, кеш по сроку не используется. Кнопки на карточке нет: точку ставит сохранение профиля
- Сортировка «По рейтингу»: баллы 0–100. До 30 собирает сам тренер: десять полей карточки по 2 (фото, текст о себе, как проходят тренировки, вид спорта, стаж, цена, формат, город, адрес, диплом) и четыре контакта на 10 баллов вместе (1 контакт — 3, 2 — 5, 3 — 8, 4 — 10). Остальные 70 приносят пользователи: до 25 — средняя оценка (без отзывов — 0), до 15 — число отзывов с потолком 20, до 20 — просмотры профиля за текущий месяц с потолком 15, до 10 — сохранения в избранном с потолком 5. Объём отзывов, просмотров и сохранений считается логарифмом: первые события весят больше. Тот же расчёт в обзоре `/me`

Вход `/auth/login?redirect=` принимает путь на этом же сайте и возвращает туда после входа. Внешние адреса отбрасываются.

**Правило:** auth проверяется в middleware/handler server fn, не только в route `beforeLoad`.

### 4.4 Безопасность auth

- Пароли: **scrypt** (Node.js crypto), min 8 + цифра + заглавная
- Timing-safe login (dummy hash при несуществующем email)
- Session rotation при login / reset password
- Cookie: HttpOnly, SameSite=Lax, Secure в production
- Password reset: одинаковый ответ (anti-enumeration)
- Регистрация на форме — почта, Google и телефон, как и вход. Telegram на формах не показывается. Роль не выбирается, аккаунт получает `user`. Почта из формы остаётся `pending_verification` без `email_verified_at`, пока человек не нажмёт кнопку в письме. Ответ формы один и тот же, сессия не открывается. Google и Яндекс подтверждают почту и записывают её на карточку тренера, если карточка уже привязана. Яндекс записывает мобильный Беларуси, если в аккаунте номера ещё нет и этот номер свободен, и ставит портрет, если своего фото нет. Телефон подтверждается SMS, если номер всё ещё принадлежит тому же аккаунту, которому код выдан
- Телефон и Telegram на регистрации пишут служебную почту `pending.{id}@users.trenio.invalid`. Пока она не заменена кодом из письма, сервер не отдаёт кабинет: `/auth/credentials`. Сохранение пароля не пишет почту, пока код не подтверждён. Если почта уже подтверждена у другого аккаунта, перенос телефона или Telegram идёт только в пустые поля и только после кода на ту почту
- SMS login и сброс пароля — только для номера с `phone_verified_at`; неизвестный номер получает тот же ответ, что и существующий, не быстрее чем за 600 мс. Сброс по SMS закрывает все сессии и открывает новую. Сброс по письму закрывает сессии и просит войти с новым паролем
- Telegram login на формах скрыт. Сервер по-прежнему знает `telegram_user_id`. Виджет и контакт — 10 минут, Mini App `initData` — 15 минут. Повтор того же подписанного доказательства отклоняется. Почта для уже сохранённого Telegram-аккаунта не обязательна, пока кабинет не потребует её. Оповещение о прямом сообщении в Telegram получает владелец карточки, если контакт подтверждён и бот с ним уже разговаривал
- Бот `@TrenioByBot`: клавиатура из восьми разделов сайта (каталог, категории, карта, сообщения, оба кабинета, заявка, контакты) и отдельная кнопка «Написать @embatron». Раздел открывает тот же путь в Mini App. «Написать @embatron» присылает кнопку, которая открывает личный чат. Внутри Telegram внизу экрана те же восемь разделов и «Вопросы»: иконка и короткая подпись, ряд листается вбок. «Вопросы» открывает чат @embatron. Если пункты не влезают, у края видна слабая стрелка. На телефоне и в Mini App над шапкой закреплена строка «Поставьте приложение на экран, чтобы оно всегда было под рукой» с кнопкой «Установить». В Mini App она ставит ярлык Telegram, в браузере телефона — значок сайта. Уже установленное приложение строку не показывает. Запуск с экрана телефона и согласие на установку записываются на этом устройстве (`trenio-app-installed`), и строка больше не появляется. Входящие `/start` принимает `POST /api/telegram/webhook` (`TELEGRAM_LOGIN_WEBHOOK_SECRET`)
- Лимиты входа, OTP и сброса лежат в Postgres (`auth_rate_buckets`). Если таблица недоступна, тот же процесс считает в памяти и не закрывает всех из-за сбоя SQL. IP берётся только из `X-Real-IP`. Лимит владельца тот же, что у остальных. Смена почты, телефона и Telegram в кабинете просит текущий пароль, только если он уже сохранён, и закрывает другие сессии. Без сохранённого пароля открытая сессия достаточна. Код из приложения для сотрудника выключен (`STAFF_TOTP_REQUIRED`): его нет ни у тренера, ни у клиента, ни на входе в кабинет. Ссылка в кабинет тренера живёт час и открывает аккаунт только кнопкой POST
- Подтверждение почты и сброс пароля уходят HTML-письмом. Ссылка в журнал не пишется. Dev: без Postfix текст письма остаётся в console (`AUTH_DEV_LOG_EMAILS` или не production); OTP в non-production возвращается в UI, если SMS.BY не включён
- Каждое письмо: словесный знак `logo-mail.png` сверху (белый фон, тёмный `trenio` и коралловый `.by`), код подтверждения отдельной жирной строкой. Серая «Отписаться» на `/mail` есть у писем, которые можно выключить: сообщения и отзывы. Код, регистрация, подтверждение почты, сброс пароля, смена пароля, вход с другого браузера, закрытие аккаунта, смена статуса карточки, письмо на редактирование профиля и письма сотрудникам о модерации идут без этой ссылки. Отправитель всегда `Trenio <noreply@trenio.by>`. `/mail` открывает блок «Письма» в настройках: клиент — `/account/settings`, тренер и клуб — `/me/settings`, сотрудник без этих ролей — `/admin/settings`. Гость сначала входит. Переключатели: сообщения, отзывы и маркетинговые рассылки. Сообщения и отзывы реально останавливают соответствующие письма. Маркетинг по умолчанию выключен. Оповещения с сайта всегда включены: переключатель стоит включённым и не нажимается, запрос выключить их отклоняется. Код, подтверждение почты, сброс пароля, смена пароля, вход с другого браузера, закрытие аккаунта, смена статуса карточки, письмо на редактирование профиля и письма сотрудникам о модерации не отключаются. После публикации отзыва письмо уходит тренеру, если включены «Отзывы» и почта подтверждена. Ответ тренера уходит автору, ответ автора — тренеру, тем же переключателем. Письмо об отзыве на неподтверждённую почту не уходит. Смена пароля пишет на подтверждённую почту и, если номер подтверждён, шлёт SMS. Вход с другого браузера пишется, только когда уже есть открытый сеанс с другим браузером. Закрытие аккаунта подтверждается письмом, а если почта не подтверждена — SMS на подтверждённый номер. Сотрудник меняет статус карточки — владельцу уходит письмо: опубликована, скрыта, в архиве или снова на модерации

### 4.6 Сообщения

Контракт для агентов: [.cursor/rules/messages.mdc](../.cursor/rules/messages.mdc), навык [.cursor/skills/trenio-messages/SKILL.md](../.cursor/skills/trenio-messages/SKILL.md).

Диалог только между аккаунтом и одним `trainer_profiles`. Исключение — одно приветствие новому тренеру от аккаунта администратора Trenioby: у диалога заполнен `host_user_id`, карточки тренера нет. Произвольный поиск собеседника и переписка user↔user не входят в модель. Одна открытая пара: уникальный индекс `(user_id, trainer_profile_id) WHERE status = 'open'`. Повторная отправка с тем же `client_id` не создаёт второе сообщение (`UNIQUE (conversation_id, client_id)`, `ON CONFLICT DO NOTHING`). `messages.id` — `bigint GENERATED ALWAYS AS IDENTITY`. Видимый текст первого сообщения инициатора — до 1000 символов, дальше до 4000. Считаются символы без разметки, один эмодзи — один символ. В поле тот же короткий редактор, что у отзыва: жирный, курсив, списки и эмодзи, включая откровенные и все оттенки кожи. Перед записью HTML чистится тем же набором тегов. В колонке хранится до 12000 символов уже с тегами. У своих сообщений под временем стоит «Доставлено», а после отметки прочтения собеседником — «Прочитано». `last_message_at` обновляется в той же транзакции, что и вставка сообщения. На карточке каталога ссылки на диалог, телефон, Instagram и Telegram нет. В блоке «Как со мной связаться» после отзывов ссылка на диалог — иконка. Клиент открывает `/account/messages?trainer={slug}` в новой вкладке. Тренер и клуб открывают `/me/messages?trainer={slug}` и остаются в своём кабинете. Старый адрес `/account/messages` для этих ролей сразу переходит в `/me/messages`, вместе с id переписки. Рядом иконки телефона (`tel:`), Instagram и Telegram. Почты среди них нет. Соцсети открываются в новой вкладке, телефон остаётся на странице. В блоке профиля рядом с трубкой виден номер. Своей карточке иконка диалога не показывается.

К сообщению можно прикрепить до 9 файлов, каждый не больше 2 МБ: фото JPG, PNG, WEBP и GIF, а также PDF, DOC, DOCX, XLS и XLSX. Тип решает содержимое файла, а не только расширение. Файлы лежат в `data/message-files/` и отдаются только участнику переписки по `/messages/files/{id}`. Для фото рядом хранится уменьшенный JPEG. В переписке снимок стоит миниатюрой 72×72 (`?preview=1`); нажатие открывает полный кадр на этой же странице, его можно повернуть влево или вправо. Сообщения клиента окрашены бирюзовым, сообщения тренера — коралловым. Свои остаются справа. В журнал не попадают имя файла и его байты, только размер и расширение. Скриншот вставляется в поле ввода через Ctrl+V (на Mac то же делает ⌘V). Сообщение может состоять только из вложения. Ctrl+Enter (на Mac ⌘+Enter) отправляет текст, который уже виден в поле, даже если счётчик ещё не успел обновиться. Обычный Enter переводит строку. На узком экране список и открытый диалог — разные шаги: диалог выезжает на весь экран под шапкой. «К списку» и свайп от левого края возвращают к списку. На телефоне стрелок между диалогами нет: они наползали на имя, соседний диалог открывают из списка. На широком экране стрелки остаются. Фон открытого диалога белый. Поле ввода поднимается над клавиатурой. На телефоне текст в поле 16px, чтобы страница не увеличивалась. Крестик на широком экране убирает открытый диалог с экрана и не меняет его статус: кнопка «Открыть» после этого не появляется. Строка в списке остаётся, её можно открыть снова. Блокировка и жалоба стоят в меню «…».

Кто что видит: клиент-инициатор — свои диалоги в `/account/messages`. Роли trainer и club видят в `/me/messages` и диалоги своего профиля, и диалоги, которые сами начали с другой карточкой. Когда создаётся аккаунт тренера (не admin и не superadmin), от аккаунта администратора Trenioby (`trenioby@gmail.com`) в «Сообщения» приходит одно приветствие. Текст берётся из «Настройки сайта» (`trainer_welcome`). Письмо подтверждения почты новому пользователю берётся оттуда же (`user_welcome`). В таблице тренеров три соседние отметки: «Сообщение» (первое сообщение в Instagram), «Ссылка» (администратор скопировал короткую ссылку `/hi/{code}`) и «Заход» (эту ссылку открыли). В колонке «Действия» сначала иконка текста: она копирует первое сообщение из «Настроек сайта» (`instagram_message`), без короткой ссылки. Слова «trenio by» в этом тексте при копировании и отправке становятся ссылкой https://trenio.by. Когда это приветствие уже отправлено, иконка текста не нажимается. Затем иконка ссылки копирует только адрес `/hi/{code}`. У опубликованного профиля она неактивна. Затем карандаш, он открывает редактирование и у опубликованного профиля тоже. Ноутбук сверяет отметки и черновик импорта с сайтом через `POST /api/sync/marks` и `POST /api/sync/trainer` (секрет `SYNC_TOKEN`). GET списка отметок короткую ссылку не отдаёт. На `/admin/site` под каждым полем написано, куда ставить `{hello}`, `{telegram}` и строку `---`. В приветствии тренеру: что это за портал, что размещение бесплатное, что выше поднимают отзывы и репутация, что вопросы пишут в этот же диалог, и что постоянный доступ к приложению даёт верификация через Telegram и Mini App. Карточки `/trainers/trenioby` нет: база отклоняет такой slug. Диалог остаётся открытым для ответа. Письмо о новом сообщении ведёт их туда же. admin и superadmin на `/admin/messages` сначала видят вкладку «Переписки (N)» со всеми диалогами, затем «Жалобы (N)». Чужой тред читают и не пишут в него, если сами не участники. Закрывает владелец профиля или сотрудник: диалог остаётся в списке, новые сообщения не отправляются. Скрыть или удалить переписку нельзя. Для обоих участников она пропадает только вместе с удалённым аккаунтом.

Лимиты отправки в Postgres, тот же `consumeRateLimit`, что у входа: 10 сообщений в минуту и 300 в сутки на отправителя. Отдельно один пользователь за календарные сутки по Минску может написать не больше чем 10 разным тренерам: считаются его сообщения в диалогах, где он инициатор. Повтор тому же тренеру в эти сутки лимит не тратит, ответ владельца профиля не считается. Одиннадцатому тренеру сервер отказывает, а кабинет показывает попап «Лимит на сегодня». Первое сообщение инициатора не длиннее 1000 видимых символов. Ошибки — на русском.

В правом углу каждой строки одна галочка значит «Доставлено», две — «Прочитано»: так отмечено последнее сообщение для того, кому оно адресовано. Если у карточки нет владельца, остаётся одна галочка. Список стоит по последней активности: сверху самый свежий диалог. Если в адресе нет конкретной переписки, при первом заходе открывается верхняя строка. Крестик убирает диалог с экрана, и верхняя строка сама больше не открывается, пока её не выберут в списке. Наведение подсвечивает строку и красит имя. В списке и в шапке диалога имя и фамилия стоят в одну строку. Кружок — фото опубликованной карточки этого аккаунта, а если карточки нет, фото аккаунта. Имя опубликованной карточки открывает `/trainers/{slug}` в новой вкладке, рядом тот же знак новой вкладки, что у имени в кабинете. У обычного аккаунта публичной страницы нет, имя остаётся текстом. Если в шапке виден клиент, строка «Тренер: …» ведёт на карточку этого диалога, тоже в новой вкладке и с тем же знаком. Панель переписки внутри карточки кабинета не рисует вторую рамку и второе скругление. Слова «Открыта» и «Закрыта» рядом с именем нет: закрытый диалог объясняется в поле ввода. На широком экране текст в поле — 14px. Адрес `?trainer=` не перебивается, пока этот диалог ещё создаётся. Клиент держит открытым поток опроса: непрочитанное для шапки и сайдбара, список и открытый тред — каждые 5 с через TanStack Query, плюс сразу при возврате на вкладку. Скрытая вкладка (`document.visibilityState`) опрос останавливает. WebSocket и SSE нет. При открытии диалога лента стоит внизу, если непрочитанное помещается в окно. Если оно выше окна, прокрутка останавливается на начале первого непрочитанного: длинный текст читается с первой строки, а не с конца. Своё только что отправленное сообщение по-прежнему прижимает ленту к низу. Сотрудник, который только читает чужой диалог, остаётся внизу. Схема не меняется, если позже появится свой PartyKit.

Письмо получателю уходит через локальный Postfix (`sendmail`) или лог (`AUTH_DEV_LOG_EMAILS` / не production), одно на паузу в 2 минуты, только на подтверждённую почту и если в настройках включены «Сообщения». Служебный адрес `pending…@users.trenio.invalid` письмо не получает. Это HTML того же вида, что и остальные письма сайта: логотип, круглое фото, имя того, кто написал, и текст сообщения. Внизу серая «Отписаться». В журнал текст не попадает. Telegram уходит любому участнику, у которого в аккаунте есть `telegram_user_id` и который уже открывал бота или Mini App (`telegram_bot_seen_at`). Текст переписки в Telegram не кладётся. Кнопка «Открыть переписку» на https открывает этот диалог в Mini App. На телефоне в браузере и в установленном приложении та же короткая фраза приходит системным push (`public/sw.js`, ключи `VAPID_*`, подписки в `push_subscriptions`). Переключатель «На телефон» в настройках кабинета включён сразу. Браузер один раз спрашивает разрешение при первом касании, дальше подписка сохраняется сама. Выключение снимает подписки этого аккаунта. В Mini App системный push недоступен, там остаётся сообщение бота. Выключенные «Сообщения» Telegram не останавливают. Шлёт бот входа (`TELEGRAM_LOGIN_BOT_TOKEN`). Если `last_read_at` этой переписки свежее 30 секунд, уведомление не отправляется. Первый счётчик непрочитанного берётся в root loader, дальше тот же запрос повторяется, пока вкладка открыта. В шапке у конверта, в меню аватара и в боковом меню кабинета у любой роли одно число: непрочитанные сообщения, которые написали этому аккаунту. Сообщение, которое отправил сам аккаунт, в это число не входит. У администратора бейдж строки есть только в диалоге, где этот аккаунт участник, и считает то же самое. Вкладка «Переписки (N)» по-прежнему считает диалоги. Число новых жалоб остаётся на вкладке «Жалобы (N)». В сайдбаре кабинета маленькие числа стоят у избранного, отзывов и сообщений. Кабинет admin и superadmin шире (`1680px`, класс `layout-staff`), кабинет тренера и клиента остаются на `1240px`.

Жалоба одна на участника и всю переписку. В шапке диалога тихая иконка флажка открывает окно: причина из короткого списка и комментарий до 1000 символов. Комментарий пишет и клиент, и тренер — каждый свою строку. Строка лежит в отдельной таблице `message_reports`: `conversation_id`, `reporter_id`, `reporter_side` (`client` или `trainer`), `reason` (русская подпись), `comment`, `status`, `created_at`. `message_id` пустой: жалоба не привязана к одному сообщению. Повтор той же пары не создаёт вторую жалобу. После записи HTML-письмо уходит всем активным admin и superadmin, со ссылкой на `/admin/messages`. В письме кружок и имя того, кто пожаловался, причина и комментарий, без текста переписки. Сотрудник видит жалобу в таблице, открывает тред, отклоняет жалобу, закрывает диалог или блокирует пару: `blocked_pairs` и статус `closed`. Закрытие и блок помечают открытые жалобы этой переписки разобранными. Комментарий жалобы в `app_logs` не пишется.

### 4.7 Адрес и геокодирование

Тренер или клуб указывает места, где проходят занятия. В форме сначала страна — она всегда Беларусь, — затем один город из поиска по населённым пунктам, затем до трёх адресов: улица и дом. Город в строку адреса второй раз не вводится. Адрес другой страны не сохраняется. Подсказки и разбор адреса идут на русском. Запрос к картам уходит отдельно от ввода и не блокирует поле. Если сервис не отвечает, адрес остаётся текстом, а форма показывает «Сервис карт временно недоступен. Попробуйте ещё раз чуть позже.» Координаты считает сервер, браузер к геокодеру не ходит.

| Поле | Смысл |
| --- | --- |
| `training_places` | JSON до трёх мест: город, район, точный адрес, широта, долгота, `geocodeStatus` |
| `address` | Строка первого места. `NULL`, если мест нет. Нужна индексу координат |
| `address_lat`, `address_lng` | Координаты первого места с точкой, `double precision`, иначе `NULL` |
| `geocode_status` | Статус первого места: `ok`, `not_found` или `pending`. `NULL`, если мест нет |

Индекс `(address_lat, address_lng)` заложен для будущего поиска «рядом». Сейчас по радиусу никто не ищет.

Геокодер — публичный Nominatim, `https://nominatim.openstreetmap.org/search`, `countrycodes=by`, `format=jsonv2`, `addressdetails=1`, `accept-language=ru`. В заголовке `User-Agent` указан Trenio.by и `Accept-Language: ru`. Это требование [usage policy](https://operations.osmfoundation.org/policies/nominatim/): не больше одного запроса в секунду с IP сервера и обязательный кеш. Процесс выдерживает паузу 1100 мс между исходящими вызовами. Таймаут 8 секунд. Ошибка сети или HTTP не роняет сохранение профиля. Если белорусский поиск пуст, сервер один раз проверяет страну без фильтра. Код страны не `by` — сохранение отклоняется. Неизвестный текст остаётся со статусом `not_found`.

`geocode_cache.query_norm` — нижний регистр без пунктуации. В строке лежат `lat`, `lng`, `display_name`, `city`, `district`, `street`, `country_code`, `created_at`. `country_code` не `by` значит, что запрос вне Беларуси. Запись старше 180 дней считается просроченной и запрашивается снова. Пустой ответ при сохранении адреса кешируется, чтобы повтор не бил внешний сервис. Подсказка кеширует только найденные адреса, чтобы незаконченный набор не закрывал следующий поиск, и кладёт в кеш сам запрос и каждое `display_name`. В подсказках нет адресов других стран.

Сохранение профиля:

1. Пустой список обнуляет зеркало первого места.
2. То же место со статусом `ok` повторно не геокодируется.
3. Новый текст без подходящей точки из кеша уходит в Nominatim. Нашли в Беларуси — `ok`, город, район и улица из ответа, уточнённые координаты. Не нашли — текст остаётся, `not_found`, координат нет. Сервис недоступен — текст остаётся, `pending`, координат нет. Адрес другой страны отклоняет всё сохранение.

Подсказки в каждом из трёх полей: пауза 400 мс, до пяти строк. В запрос к картам подставляется уже выбранный город, в поле остаётся улица и дом. Пункт «Не нашли адрес? Просто сохраните текст» пишет строку без координат (`pending`, затем догеокодизация на сервере). Если карты не ответили, подсказок нет и под полем временная ошибка; это не «адрес не найден». Выбор подсказки заполняет улицу, район и координаты; город берётся из поля города. Сервер принимает координаты, только если они совпали с кешем.

На публичной карточке места — плашки с иконкой адреса: город и улица в одной строке, без района. Нажатие на плашку с координатами переводит карту на эту точку, не уходя со страницы. Карта Leaflet (тайлы `tile.openstreetmap.org`, zoom 16, без зума колёсиком, без строки Leaflet и © OpenStreetMap) рисуется в браузере, если есть хотя бы одна точка. Пока скрипт карты не пришёл, на месте карты стоит блок той же высоты. Кнопка «Проложить маршрут» открывает Яндекс Карты: `https://yandex.by/maps/?rtext=~{lat},{lng}&rtt=auto` для выбранного места. Без координат остаётся список.

Общая карта — `/map`, функция `listMapAreaFn`. На неё попадают только опубликованные профили и только места со статусом `ok`. Запрос идёт по границам кадра: если разных точек больше 80, ответ — группы с числом тренеров, иначе отдельные метки. Список — страница из 12 ближайших к центру кадра; следующая страница приходит, когда пользователь докручивает список. Весь каталог в браузер не отдаётся. Тайлы те же, колесо мыши карту не масштабирует. Карта не прокручивает страницу и не прыгает к карточке. Кнопка «Фильтры» собирает поле вида спорта, ряд направлений первого уровня и виды второй ступени только у выбранного направления, затем аудиторию, формат, цену и опыт. Иконки направлений — те же изображения, что в hero на главной; у выбранного направления иконка белая. В `?sports=` slug родителя оставляет всё направление, slug вида второй ступени — только этот вид. В шапке иконка метки ведёт на `/map`. Баннер «Посмотреть на карте» передаёт общее направление страницы, а не вложенный вид. Со страницы города (`/city/{slug}` и страницы вида в городе) баннер также передаёт `?city=` — slug из `city-pages`. Карта тогда открывается в центре этого города и оставляет только места с тем же названием города. `?city=` не индексируется. Смена направления на карте сохраняет город в адресе. Наведение на метку открывает фирменную подсказку со ссылками на профили (один тренер или список в этой точке); нажатие оставляет её открытой. Нажатие на группу приближает кадр. Наведение на карточку подсвечивает метки этого тренера, наведение на метку — карточку в списке. На ширине от 960px карта слева, карточки справа по три в ряд. Уже этого карта стоит над списком: одна колонка до 720px и три колонки шире. Порядок страницы — расстояние до центра кадра. Если координаты посетителя не пришли или страна не Беларусь, карта открывается от центра Минска и больше сама не сдвигается. На ширине до 960px первый кадр открывается на шаг шире, чем на широком экране. Кнопка «Моё местоположение» вызывает Geolocation API и не ходит во внешний геокодер. Точка вне Беларуси карту не сдвигает. Посетителю об этом ничего не пишется: отказ браузера и точка вне страны уходят отдельной строкой `map.locate` в тот же журнал `app_logs`, что и сообщения. Координаты в строку не попадают. У вошедшего строка видна на вкладке «Логи» его аккаунта. Несколько тренеров в одной точке делят метку. Если скрипт карты не загрузился, на месте карты остаётся список уже полученной страницы. Без сети тайлы не приходят, новый кадр не загружается, уже показанные метки и карточки остаются.

Отдельной кнопки «Найти на карте ещё раз» на странице профиля нет: сохранение само спрашивает сервис карт. Подпись «Координаты найдены» у адреса не показывается. Если точка не встала, остаётся «Адрес не найден» или «На карте ещё не отмечен». Если сервис не ответил, к сообщению о сохранении добавляется временная ошибка. Точку руками не ставят. Убрать лишний адрес можно иконкой справа от поля; перед удалением форма спрашивает подтверждение.

Если объём вырастет и публичный Nominatim перестанет подходить, запасной путь — свой Photon (геокодер на данных OpenStreetMap) за тем же серверным интерфейсом. Ключи Яндекса и Google не используются.

### 4.8 Журнал действий

Контракт для агентов: [.cursor/rules/logging.mdc](../.cursor/rules/logging.mdc), навык [.cursor/skills/trenio-logging/SKILL.md](../.cursor/skills/trenio-logging/SKILL.md). Диагностика — команда `/diagnosis`.

Две таблицы, обе без срока хранения. `app_logs` — входы, почта, формы, карта и ошибки. `trainer_journal` — добавление карточки (`trainer.add`), обновление импорта (`trainer.sync`), появление в каталоге (`trainer.appear`), снятие с каталога (`trainer.withdraw`), действия с карточкой, привязка и пароль по короткой ссылке, а также вход и действия аккаунта, если их делает тренер или клуб. Время — `created_at`. Пароль, код, ссылка и текст переписки туда не пишутся. Строки не удаляются по давности. Обе таблицы создаёт `npm run logs:install`. `db:push` для них не использовать: живой enum `otp_purpose` не совпадает с Drizzle.

Пишется домен и действие (`auth.login`, `email.send`, `form.review`, `map.area`, `message.send`, `ajax.http`, `system.unhandled` и остальные из навыка), итог (`success`, `failure`, `denied`, `skipped`), короткое сообщение, почта или маска телефона, id аккаунта, цель (slug или id переписки), маршрут, код ошибки и обрезанный stack. IP берётся только из `X-Real-IP`.

В журнал не попадают пароль, токен сессии, ссылка сброса, код из SMS или письма, `initData`, cookie и HTML переписки. Текст письма в консоль разработки по-прежнему пишет `AUTH_DEV_LOG_EMAILS`, в базу уходит только факт и тема. Опрос списка и непрочитанного пишется только при сбое. Браузер сообщает свои ошибки и ответы 500 через `reportClientLogsFn`, не больше 20 событий за 5 минут с одного IP.

Вкладки «Логи» на `/admin/accounts/$id` и `/admin/trainers/$slug` смешивают этот журнал с прежней историей из сессий, токенов и отзывов. Stack и context в кабинете не показываются. Порог записи — `LOG_LEVEL`, по умолчанию `info`. Удаление своего аккаунта пишет `account.delete` («Пользователь удалил аккаунт») и не стирает почту, маску телефона, IP и user-agent. Эти строки остаются. Восстановление пишет `account.restore`. По истечении шести месяцев `account.purge` фиксирует анонимизацию аккаунта, а журнал не чистится.

## 6. PWA — обязательное требование проекта

**Trenio.by — 100% PWA-совместимый проект.** Любая новая фича должна учитывать installable web app.

### 6.1 Целевой чеклист

| #   | Требование                                                               | Статус           |
| --- | ------------------------------------------------------------------------ | ---------------- |
| 1   | Web App Manifest (`name`, `icons`, `theme_color`, `display: standalone`) | ✓ (`public/manifest.webmanifest`) |
| 2   | Service Worker (precache + runtime caching)                              | Push only (`public/sw.js`). Precache ещё planned |
| 3   | Offline fallback route (`/offline`)                                      | Planned          |
| 4   | HTTPS в production                                                       | Required         |
| 5   | Responsive icons 192/512                                                 | ✓ (`public/icons/`) |
| 6   | `viewport` + `theme-color` meta                                          | ✓ (`__root.tsx`) |
| 7   | Не ломать SW при deploy (cache busting)                                  | Required         |
| 8   | Auth cookies совместимы с PWA scope                                      | ✓ SameSite=Lax   |

### 6.2 Правила реализации

- Не использовать APIs, недоступные в SW context, без fallback
- Статика для UI и PWA — `public/` (категории, логотип, иконки, manifest). `public/sw.js` только показывает push о новом сообщении и не кэширует страницы. Precache и `/offline` ещё planned, §6.3
- Новые route — учитывать offline UX (empty state, не белый экран)
- SSR страницы должны hydrates без ошибок в standalone mode
- Карта мест тренера ходит в тайлы OpenStreetMap из браузера. Без сети остаётся список адресов, блок карты не схлопывается
- Общая карта `/map` ходит в те же тайлы и запрашивает только текущий кадр. Если скрипт карты не загрузился, на месте карты остаётся список уже полученной страницы той же высоты. Без сети тайлы не приходят, новый кадр не загружается, уже показанные метки остаются
- На телефоне и в Mini App шапка держит строку установки на экран. В браузере это значок сайта, в Mini App — ярлык Telegram. Уже установленное приложение строку скрывает и запоминает это на устройстве, чтобы строка не вернулась
- Тестировать: Lighthouse PWA audit, «Add to Home Screen» на Android/iOS

src/routes/offline.tsx

## 7. Mobile-first — обязательное требование

**Mobile-first:** дизайн и реализация начинаются с viewport ≤768px, затем расширяются.

### 7.1 Breakpoint

- Mobile: `< 768px` (`useIsMobile`, Tailwind `md:` = 768px)
- Touch targets: min **44×44px** для интерактива
- Auth forms: single column on mobile (`auth-styles.tsx` media queries)

### 7.2 Чеклист для UI-изменений

| #   | Проверка                                                         |
| --- | ---------------------------------------------------------------- |
| 1   | Layout не ломается на 320px width                                |
| 2   | Нет horizontal scroll на mobile (кроме intentional carousels)    |
| 3   | Header/burger/mega menu работают на touch                        |
| 4   | Forms usable с виртуальной клавиатурой                           |
| 5   | Font size ≥14px для body, контраст WCAG AA                       |
| 6   | Sticky/fixed elements не перекрывают контент                     |
| 7   | `@media (max-width: …)` или Tailwind mobile-first (`sm:`, `md:`) |
| 8   | Desktop-only features имеют mobile alternative                   |

### 7.3 Компоненты

- `SiteHeader` — responsive nav, login icon
- `AuthStyles` — mobile grid collapse
- shadcn `Sheet` / `Drawer` — предпочтительны для mobile overlays
- Карточки каталога — stack on mobile, grid on desktop

### 7.4 Единая layout-сетка
