Единый инженерный документ проекта. Продуктовый контекст — [PRODUCT.md](./PRODUCT.md), доменная модель — [ACCOUNT_MODEL.md](./ACCOUNT_MODEL.md).

**Домен:** trenio.by · **Рынок:** Беларусь · **MVP:** каталог тренеров и клубов, конверсия через контактный клик.

## 1. Архитектура

```
Browser / PWA client
        │
        ▼
```

## 3. Маршрутизация

File-based TanStack Router: `src/routes/<name>.tsx` → URL.

| Паттерн              | Пример                             |
| -------------------- | ---------------------------------- |
| `index.tsx`          | `/`                                |
| `search.tsx`         | `/search`                          |
| `trainers.$slug.tsx` | `/trainers/:slug`                  |
| `auth.login.tsx`     | `/auth/login`                      |
| `__root.tsx`         | App shell, session in `beforeLoad` |

Root context: `{ queryClient, user: PublicUser | null }` — сессия через `getSessionFn`. У вошедшего в шапке стоит его аватар: фото аккаунта, а у тренера и клуба — первое фото профиля. Рядом с аватаром у тренера и клуба виден ник (Instagram или адрес профиля). У обычного пользователя ника в шапке нет. На узком экране, где поиск в шапке скрыт, остаётся только аватар.

### Город посетителя

На страницах категории (`/categories/yoga` и вложенные) город в фильтре подставляется сам, если IP удалось сопоставить с населённым пунктом Беларуси. Библиотека — [`ip-location-api`](https://www.npmjs.com/package/ip-location-api) с бесплатной базой GeoLite2 City (язык `ru`, режим `smallMemory`). База лежит в `data/geoip/` и не коммитится. Перед выкладкой: `npm run geoip:update`.

IP берётся из `CF-Connecting-IP` или `X-Real-IP`. Если в запросе только локальный адрес (так у `trenio.local` за Apache), браузер один раз узнаёт свой публичный IP и сервер ищет его в той же базе. Город подставляется только когда это населённый пункт Беларуси. Результат и ручной выбор пишутся в cookie `trenio_place` на год. «Сбросить» очищает город и больше не подставляет его, пока посетитель не выберет населённый пункт снова. IP в cookie не хранится. В базе те же поля, что просит `ILA_FIELDS`: страна, город, радиус и координаты. Координаты нужны странице `/map`, чтобы поставить ближе тех, чьё место тренировки ближе к точке IP. В cookie координаты не пишутся.

Поиск на главной, в шапке, на страницах 403 и 404 и при пустой выдаче — одна форма `CatalogSearchForm`. Виды спорта берутся из таксономии (`src/lib/catalog/sport-taxonomy.ts`). Город в поле — определённый или сохранённый населённый пункт, иначе «Минск». Тот же город выбран в фильтре категории; в шапке категории поиск заранее заполнен названием вида спорта.

База GeoLite2 создана MaxMind и доступна на [maxmind.com](https://www.maxmind.com).

### 4.2 Схема (MVP auth)

| Таблица                     | Назначение                                              |
| --------------------------- | ------------------------------------------------------- |
| `users`                     | email, phone (`+375 29 123-45-67`), password_hash, avatar_path, telegram_user_id, status, last_signup_intent |
| `user_roles`                | RBAC: user, trainer, club, admin, superadmin            |
| `sessions`                  | HttpOnly cookie, срок 3 недели (token hash)             |
| `password_reset_tokens`     | Сброс пароля (30 мин)                                   |
| `email_verification_tokens` | Подтверждение e-mail                                    |
| `auth_otp_challenges`       | SMS-коды: login, verify_phone, register, reset_password. Номер в челлендже — цифры `375XXXXXXXXX` для SMS.BY |
| `trainer_reviews`           | Отзыв авторизованного пользователя о тренере (один на пару user + slug). Статус: на модерации, опубликован, отклонён. `moderation_note` виден автору. Переписка тренера и автора отзыва — `messages`; кнопка «Ответить» только у того, чей сейчас ход |
| `user_favorites`            | Избранные тренеры и клубы авторизованного пользователя (один на пару user + тип + slug) |
| `conversations`, `messages`, `message_attachments`, `conversation_reads`, `message_reports`, `blocked_pairs` | Переписка пользователь ↔ опубликованный профиль. Вложения лежат в `data/message-files/`, не в `public/`. Таблицу вложений ставит `npm run messages:install` (не `db:push`). См. §4.6 |
| `trainer_profiles`          | Черновик карточки тренера: имя и фамилия отдельными полями (`first_name`, `last_name`; `full_name` — их склейка), текст, до четырёх видов спорта, один город Беларуси, стаж от 1, цена разового занятия может быть пустой — тогда на карточке «договорная», Instagram, Telegram, почта владельца (та же, что для входа), до девяти фото и до пяти сертификатов или дипломов с подписью (PNG, JPG, PDF и другие файлы; на профиле ссылка в новое окно). Импорт кладёт в виды спорта только то, чему человек учит; увлечение остаётся отдельно. Текст Instagram сохраняется дословно в «Текст из источника». Мобильный номер из биографии, актуального «Обо мне» и закрепов записывается в поле телефона карточки в виде `+375 29 123-45-67` и не подтверждается; из текстов карточки он убирается. На карточку импорт пишет «Как меня представить» и «Как проходят мои тренировки» короткими фразами и только из биографии, актуального «Обо мне» и закреплённых постов. Лицо берётся из фото профиля. Ещё снимки — из закрепов, всего не больше девяти. Снимок с подписью «диплом», «сертификат» или «удостоверение» сохраняется как документ, а не как фото профиля. Поле телефона карточки хранится в виде `+375 29 123-45-67`. На публичной странице номер скрыт, пока владелец не подтвердит его SMS. Импорт без согласия остаётся черновиком («на модерации»). Род определяется при импорте по имени и виден только сотруднику. Привязка здоровается этим именем и выбирает «был» или «была». Адрес страницы и ник равны Instagram (`/trainers/{handle}`), старые именные адреса перенаправляются. До трёх мест тренировок в Беларуси лежит в `training_places`. Первое место дублируется в `address`, `address_lat`, `address_lng`, `geocode_status`, см. §4.7. Ссылка `/trainers/claim/{token}` видна сотруднику на странице редактирования, пока карточка не опубликована и не привязана: иконка копирует полный адрес, проверка сверяет, что она ещё открывает непривязанную карточку. В таблице тренеров этой проверки нет. После публикации или привязки адрес из кабинета пропадает и открывает публичный профиль. Привязка — после оферты, ника, почты и пароля: аккаунт сразу активен, тренер попадает на редактирование карточки. Ник уникален и не редактируется, смена только через поддержку. Сложность пароля показывается при вводе. Карточка профиля выезжает при первом открытии. В каталог карточка попадает только после публикации |
| `trainer_welcomes`          | Отдельная таблица заявок с `/join/trainer`: канал, Instagram, Telegram и мобильный РБ `+375 29 123-45-67`. Без аккаунта. `link_sent_at` пустой, пока тренер не откроет предварительный профиль по `/trainers/claim/{token}`. Тогда по совпавшему контакту пишется время: по кандидату работа проведена и ссылка дошла |
| `trainer_profile_views`     | Посещение опубликованного профиля: один посетитель и один день Europe/Minsk. Владелец не пишется. Кабинет `/me` показывает сутки, неделю и месяц и разницу с предыдущим таким же периодом |
| `geocode_cache`             | Кеш ответов Nominatim: координаты, город, район, улица и код страны. Ключ — нормализованный запрос. См. §4.7 |
| `app_logs`                  | Операционный журнал: входы, почта, SMS, аккаунт, формы, карта, гео, сообщения, AJAX и необработанные ошибки. Хранится 30 дней. См. §4.8 |

### 4.3 Server functions

Все мутации и приватные данные — через `createServerFn` в `src/lib/auth/functions.ts`:

- `getSessionFn`, `loginFn`, `signupFn`, `logoutFn`
- `requestSmsLoginFn`, `confirmSmsLoginFn`
- `loginWithTelegramFn`, `loginWithTelegramWebAppFn`, `getTelegramLoginConfigFn`
- `forgotPasswordFn`, `requestPasswordResetSmsFn`, `confirmPasswordResetSmsFn`
- `resetPasswordFn`, `verifyEmailFn`, `updateProfileFn` — имя и фамилия текущего аккаунта двумя полями; `setAccountAvatarFn` — фото в `public/avatars/`
- `changePasswordFn` — смена пароля из кабинета по текущему паролю, текущая сессия сохраняется
- `requestAccountEmailCodeFn`, `confirmAccountEmailCodeFn` — смена почты кодом из письма
- `requestAccountPhoneCodeFn`, `confirmAccountPhoneCodeFn` — привязка телефона SMS-кодом. Подтверждённый номер записывается и в карточку тренера, если она есть
- `listTrainerReviewsFn`, `createTrainerReviewFn` — отзывы профиля тренера; создание только с сессией (`requireAuthMiddleware`). Новый отзыв уходит на модерацию
- `setTrainerReviewStatusFn` — публикация или отклонение отзыва, только `admin` и `superadmin`. Отклонение требует комментарий клиенту и шлёт ему письмо
- `listTrainerRatingSummariesFn` — средняя оценка и число опубликованных отзывов по тренерам для карточек каталога
- `listFavoritesFn`, `toggleFavoriteFn` — избранное только с сессией, без срока хранения. Список и переключение вызываются с клиента после отрисовки, без перезагрузки страницы. Гость уходит на вход. Счётчик в шапке виден вошедшему пользователю и ведёт в избранное его кабинета: `/account/favorites` или `/me/favorites`
- `getAdminShellFn`, `getAdminOverviewFn`, `getAdminTrainersFn`, `saveAdminTrainerFn`, `getAdminTrainerDetailFn`, `saveAdminTrainerPhotoFn`, `getAdminReviewsFn`, `getAdminAccountsFn`, `getAdminFinanceFn`, `getAdminSettingsFn` — отдельные серверные функции разделов `/admin/*` для `admin` и `superadmin`. Виды спорта — не больше четырёх категорий второго уровня. Город выбирается из населённых пунктов Беларуси. Стаж — целое число от 1. Цена — целое число или пустое поле: пустое сохраняется как null, на карточке «договорная». Карточка `/admin/trainers/$slug` редактирует поля в том же порядке, что и кабинет тренера. В кабинете тренера отдельного заголовка нет: «Как меня представить» — обязательный текст блока «Обо мне». У сотрудника имя и заголовок в одной строке, город отдельным полем, стаж выше контактов, Instagram и Telegram внизу, формат занятий и аудитория из таксономии, до девяти фото. Телефон карточки равен телефону привязанного аккаунта и подтверждается SMS. Входы, логи и прочие данные видит только сотрудник. «О себе» и «Как проходят мои тренировки» — тот же короткий редактор, что у отзыва: жирный, курсив, списки. Фото можно перетащить: первое становится главным. При сохранении фото сервер пишет оригинал до 1600 px и производные `s128`, `c320`, `c640`, `w960` рядом с ним, без увеличения и без метаданных. Карточки, поиск, профиль и аватары запрашивают производный файл и возвращаются к оригиналу, если его ещё нет. Файлы лежат в `public/trainers/` и `public/avatars/`. Dev-сервер отдаёт их с диска, не дожидаясь перезапуска. Оболочка кабинета одна, у пользователя и тренера свои маршруты: `/account/*` и `/me/*`. Имя тренера редактируется в настройках и копируется в карточку
- `getUserCabinetFn` — свои отзывы, телефон и статус телефона. Кабинет: `/account/reviews`, `/account/messages`, `/account/bookings`, `/account/favorites`, `/account/settings`
- Переписка — `src/lib/messages/functions.ts`, все вызовы `POST` и `requireAuthMiddleware`. См. §4.6
- `submitTrainerWelcomeFn` — публичная заявка с `/join/trainer`, `POST`, без сессии. Пишет строку в `trainer_welcomes`: Instagram, Telegram и мобильный РБ. Ссылка «У меня нет Instagram» принимает Telegram или телефон. Лимит по `X-Real-IP`. Когда тренер открывает черновик по `/trainers/claim/{token}`, `getTrainerClaimFn` ставит `link_sent_at` у заявки с тем же контактом. Первое открытие не перезаписывается
- `getHomeStatsFn` — блок «в цифрах» на главной: число профилей тренеров кроме архива, виды спорта и города из `trainer_profiles`, средний стаж в годах. В среднее входят только карточки, где стаж указан (от 1)
- `getOwnTrainerProfileFn`, `saveOwnTrainerProfileFn` — черновик карточки тренера для ролей trainer и club. Имя и фамилия берутся из аккаунта: форма профиля их не показывает и `users` не перезаписывает. Сохранение до трёх адресов геокодирует текст, если координаты ещё не подтверждены. Адрес вне Беларуси отклоняется. См. §4.7
- `getPublicTrainerContactsFn` — контакты публичного профиля. Телефон отдаётся только после SMS. Telegram — только при `telegram_verified_at`. Почта на странице — почта входа владельца и видна только после `users.email_verified_at`. У карточки без владельца почта скрыта. Instagram виден, как только заполнен
- `requestAccountEmailCodeFn`, `confirmAccountEmailCodeFn` — один код на почту входа. Подтверждение пишет адрес в `users` и ту же почту в карточку тренера. Обзор и настройки вызывают этот код; отдельные функции почты карточки делают то же самое
- `recordTrainerProfileViewFn`, `getOwnTrainerViewStatsFn` — запись и сводка посещений профиля. См. таблицу `trainer_profile_views`
- `suggestAddress` — подсказки адреса только по Беларуси и на русском, `POST`, `requireAuthMiddleware`, не чаще одного запроса в секунду на пользователя. Ответ — `{ displayName, city, district, street, lat, lng }`, без сырых полей Nominatim
- `getTrainerAddressFn` — публичные места карточки для `/trainers/$slug`: город, район, адрес и координаты, координаты только если статус `ok`
- `listMapAreaFn` — один кадр публичной карты `/map`. В браузер не уходит весь каталог: в ответе группы точек или отдельные метки этого кадра и одна страница ближайших к его центру тренеров. Только опубликованные профили и места со статусом `ok`. Без телефона и почты. Черновик и адрес без точки не попадают в ответ
- `adminGeocodeTrainer` — повторное геокодирование сохранённых мест, `POST`, только `admin` и `superadmin`, кеш по сроку не используется
- Сортировка «По популярности»: коэффициент 0–100. До 50 даёт средняя оценка (без отзывов — 0), до 25 — число отзывов с потолком 20, до 15 — просмотры профиля за текущий месяц с потолком 30, до 10 — сохранения в избранном с потолком 10. Объём считается логарифмом: первые события весят больше. Тот же расчёт в обзоре `/me`

Вход `/auth/login?redirect=` принимает путь на этом же сайте и возвращает туда после входа. Внешние адреса отбрасываются.

**Правило:** auth проверяется в middleware/handler server fn, не только в route `beforeLoad`.

### 4.4 Безопасность auth

- Пароли: **scrypt** (Node.js crypto), min 8 + цифра + заглавная
- Timing-safe login (dummy hash при несуществующем email)
- Session rotation при login / reset password
- Cookie: HttpOnly, SameSite=Lax, Secure в production
- Password reset: одинаковый ответ (anti-enumeration)
- SMS login и сброс пароля — только для номера с `phone_verified_at`; неизвестный номер получает тот же ответ, что и существующий
- Telegram login — только для уже привязанного `telegram_user_id`; виджет (10 мин) и Mini App `initData` (24 ч)
- Лимиты попыток входа и OTP — в памяти процесса
- Dev: `AUTH_DEV_LOG_EMAILS=true` — ссылки в console; OTP в non-production возвращается в UI, если SMS.BY не включён

### 4.6 Сообщения

Контракт для агентов: [.cursor/rules/messages.mdc](../.cursor/rules/messages.mdc), навык [.cursor/skills/trenio-messages/SKILL.md](../.cursor/skills/trenio-messages/SKILL.md).

Диалог только между аккаунтом и одним `trainer_profiles`. Произвольный поиск собеседника и переписка user↔user не входят в модель. Одна открытая пара: уникальный индекс `(user_id, trainer_profile_id) WHERE status = 'open'`. Повторная отправка с тем же `client_id` не создаёт второе сообщение (`UNIQUE (conversation_id, client_id)`, `ON CONFLICT DO NOTHING`). `messages.id` — `bigint GENERATED ALWAYS AS IDENTITY`. Видимый текст первого сообщения инициатора — до 1000 символов, дальше до 4000. Считаются символы без разметки, один эмодзи — один символ. В поле тот же короткий редактор, что у отзыва: жирный, курсив, списки и эмодзи, включая откровенные и все оттенки кожи. Перед записью HTML чистится тем же набором тегов. В колонке хранится до 12000 символов уже с тегами. У своих сообщений под временем стоит «Доставлено», а после отметки прочтения собеседником — «Прочитано». `last_message_at` обновляется в той же транзакции, что и вставка сообщения. На карточке и в блоке «Как со мной связаться» после отзывов ссылка на диалог — иконка. Клиент открывает `/account/messages?trainer={slug}` в новой вкладке. Тренер и клуб открывают `/me/messages?trainer={slug}` и остаются в своём кабинете. Старый адрес `/account/messages` для этих ролей сразу переходит в `/me/messages`, вместе с id переписки. Рядом иконки телефона (`tel:`), Instagram, Telegram и почты. Соцсети и почта открываются в новой вкладке, телефон остаётся на странице. В блоке профиля рядом с трубкой виден номер. Своей карточке иконка диалога не показывается.

К сообщению можно прикрепить до 9 файлов, каждый не больше 2 МБ: фото JPG, PNG, WEBP и GIF, а также PDF, DOC, DOCX, XLS и XLSX. Тип решает содержимое файла, а не только расширение. Файлы лежат в `data/message-files/` и отдаются только участнику переписки по `/messages/files/{id}`. Для фото рядом хранится уменьшенный JPEG. В переписке снимок стоит миниатюрой 72×72 (`?preview=1`); нажатие открывает полный кадр на этой же странице, его можно повернуть влево или вправо. Сообщения клиента окрашены бирюзовым, сообщения тренера — коралловым. Свои остаются справа. В журнал не попадают имя файла и его байты, только размер и расширение. Скриншот вставляется в поле ввода через Ctrl+V (на Mac то же делает ⌘V). Сообщение может состоять только из вложения. Ctrl+Enter (на Mac ⌘+Enter) отправляет текст, который уже виден в поле, даже если счётчик ещё не успел обновиться. Обычный Enter переводит строку. На узком экране список и открытый диалог — разные шаги: диалог занимает экран под шапкой, «К списку» возвращает к списку.

Кто что видит: клиент-инициатор — свои диалоги в `/account/messages`. Роли trainer и club видят в `/me/messages` и диалоги своего профиля, и диалоги, которые сами начали с другой карточкой. Письмо о новом сообщении ведёт их туда же. admin и superadmin читают чужой тред в `/admin/messages` и не пишут в чужой. Закрывает владелец профиля или сотрудник: диалог остаётся в списке, новые сообщения не отправляются. Скрыть или удалить переписку нельзя. Для обоих участников она пропадает только вместе с удалённым аккаунтом.

Лимиты отправки в памяти процесса, тот же `consumeRateLimit`, что у входа: 10 сообщений в минуту и 300 в сутки на отправителя. Отдельно один пользователь за календарные сутки по Минску может написать не больше чем 10 разным тренерам: считаются его сообщения в диалогах, где он инициатор. Повтор тому же тренеру в эти сутки лимит не тратит, ответ владельца профиля не считается. Одиннадцатому тренеру сервер отказывает, а кабинет показывает попап «Лимит на сегодня». Первое сообщение инициатора не длиннее 1000 видимых символов. Ошибки — на русском.

Список стоит по последней активности: сверху самый свежий диалог. Если в адресе нет конкретной переписки, открывается верхняя строка. Наведение подсвечивает строку и красит имя. В списке и в шапке диалога имя и фамилия стоят в одну строку. Слова «Открыта» и «Закрыта» рядом с именем нет: закрытый диалог объясняется в поле ввода. Текст в поле — 14px. Адрес `?trainer=` не перебивается, пока этот диалог ещё создаётся. Клиент держит открытым поток опроса: непрочитанное для шапки и сайдбара, список и открытый тред — каждые 5 с через TanStack Query, плюс сразу при возврате на вкладку. Скрытая вкладка (`document.visibilityState`) опрос останавливает. WebSocket и SSE нет. Схема не меняется, если позже появится свой PartyKit.

Письмо получателю уходит через Resend или лог (`AUTH_DEV_LOG_EMAILS` / не production), одно на паузу в 2 минуты, без текста переписки. Если получатель — владелец профиля и у него есть `telegram_user_id`, то же короткое уведомление шлёт бот входа (`TELEGRAM_LOGIN_BOT_TOKEN`). Если `last_read_at` этой переписки свежее 30 секунд, уведомление не отправляется. Первый счётчик непрочитанного берётся в root loader, дальше тот же запрос повторяется, пока вкладка открыта. В шапке у конверта всегда видно число. В сайдбаре кабинета маленькие числа стоят у избранного, отзывов и сообщений. Кабинет admin и superadmin шире (`1680px`, класс `layout-staff`), кабинет тренера и клиента остаются на `1240px`.

Жалоба одна на участника и всю переписку. В шапке диалога тихая иконка флажка открывает окно: причина из короткого списка и комментарий до 1000 символов. Комментарий пишет и клиент, и тренер — каждый свою строку. Строка лежит в отдельной таблице `message_reports`: `conversation_id`, `reporter_id`, `reporter_side` (`client` или `trainer`), `reason` (русская подпись), `comment`, `status`, `created_at`. `message_id` пустой: жалоба не привязана к одному сообщению. Повтор той же пары не создаёт вторую жалобу. После записи письмо уходит всем активным admin и superadmin, со ссылкой на `/admin/messages`. В письме причина и комментарий, без текста переписки. Сотрудник видит жалобу в таблице, открывает тред, отклоняет жалобу, закрывает диалог или блокирует пару: `blocked_pairs` и статус `closed`. Закрытие и блок помечают открытые жалобы этой переписки разобранными. Комментарий жалобы в `app_logs` не пишется.

### 4.7 Адрес и геокодирование

Тренер или клуб указывает до трёх мест, где проходят занятия. Блок называется «Места, где я тренирую». Страна фиксирована: Беларусь. Адрес другой страны не сохраняется. Подсказки и разбор адреса идут на русском. Координаты считает сервер, браузер к геокодеру не ходит.

| Поле | Смысл |
| --- | --- |
| `training_places` | JSON до трёх мест: город, район, точный адрес, широта, долгота, `geocodeStatus` |
| `address` | Строка первого места. `NULL`, если мест нет. Нужна индексу координат |
| `address_lat`, `address_lng` | Координаты первого места с точкой, `double precision`, иначе `NULL` |
| `geocode_status` | Статус первого места: `ok`, `not_found` или `pending`. `NULL`, если мест нет |

Индекс `(address_lat, address_lng)` заложен для будущего поиска «рядом». Сейчас по радиусу никто не ищет.

Геокодер — публичный Nominatim, `https://nominatim.openstreetmap.org/search`, `countrycodes=by`, `format=jsonv2`, `addressdetails=1`, `accept-language=ru`. В заголовке `User-Agent` указан Trenio.by и `Accept-Language: ru`. Это требование [usage policy](https://operations.osmfoundation.org/policies/nominatim/): не больше одного запроса в секунду с IP сервера и обязательный кеш. Процесс выдерживает паузу 1100 мс между исходящими вызовами. Таймаут 8 секунд. Ошибка сети или HTTP не роняет сохранение профиля. Если белорусский поиск пуст, сервер один раз проверяет страну без фильтра. Код страны не `by` — сохранение отклоняется. Неизвестный текст остаётся со статусом `not_found`.

`geocode_cache.query_norm` — нижний регистр без пунктуации. В строке лежат `lat`, `lng`, `display_name`, `city`, `district`, `street`, `country_code`, `created_at`. `country_code` не `by` значит, что запрос вне Беларуси. Запись старше 180 дней считается просроченной и запрашивается снова. Пустой ответ при сохранении адреса кешируется, чтобы повтор не бил внешний сервис. Подсказка кеширует только найденные адреса, чтобы незаконченный набор не закрывал следующий поиск, и кладёт в кеш сам запрос и каждое `display_name`. В подсказках нет адресов других стран.

Сохранение профиля:

1. Пустой список обнуляет зеркало первого места.
2. То же место со статусом `ok` повторно не геокодируется.
3. Новый текст без подходящей точки из кеша уходит в Nominatim. Нашли в Беларуси — `ok`, город, район и улица из ответа, уточнённые координаты. Не нашли — текст остаётся, `not_found`, координат нет. Сервис недоступен — текст остаётся, `pending`, координат нет. Адрес другой страны отклоняет всё сохранение.

Подсказки в каждом из трёх полей: пауза 400 мс, до пяти строк. Пункт «Не нашли адрес? Просто сохраните текст» пишет строку без координат (`pending`, затем догеокодизация на сервере). Выбор подсказки заполняет город, район, улицу и координаты; сервер принимает координаты, только если они совпали с кешем.

На публичной карточке места — плашки с иконкой адреса: город и улица в одной строке, без района. Нажатие на плашку с координатами переводит карту на эту точку, не уходя со страницы. Карта Leaflet (тайлы `tile.openstreetmap.org`, zoom 16, без зума колёсиком, без строки Leaflet и © OpenStreetMap) рисуется в браузере, если есть хотя бы одна точка. Пока скрипт карты не пришёл, на месте карты стоит блок той же высоты. Кнопка «Проложить маршрут» открывает Яндекс Карты: `https://yandex.by/maps/?rtext=~{lat},{lng}&rtt=auto` для выбранного места. Без координат остаётся список.

Общая карта — `/map`, функция `listMapAreaFn`. На неё попадают только опубликованные профили и только места со статусом `ok`. Запрос идёт по границам кадра: если разных точек больше 80, ответ — группы с числом тренеров, иначе отдельные метки. Список — страница из 12 ближайших к центру кадра; следующая страница приходит, когда пользователь докручивает список. Весь каталог в браузер не отдаётся. Тайлы те же, колесо мыши карту не масштабирует. Карта не прокручивает страницу и не прыгает к карточке. Кнопка «Фильтры» собирает поле вида спорта, ряд направлений первого уровня и виды второй ступени только у выбранного направления, затем аудиторию, формат, цену и опыт. Иконки направлений — те же изображения, что в hero на главной; у выбранного направления иконка белая. В `?sports=` slug родителя оставляет всё направление, slug вида второй ступени — только этот вид. В шапке иконка метки ведёт на `/map`. Баннер «Посмотреть на карте» передаёт общее направление страницы, а не вложенный вид. Со страницы города (`/city/{slug}` и страницы вида в городе) баннер также передаёт `?city=` — slug из `city-pages`. Карта тогда открывается в центре этого города и оставляет только места с тем же названием города. `?city=` не индексируется. Смена направления на карте сохраняет город в адресе. Наведение на метку открывает фирменную подсказку со ссылками на профили (один тренер или список в этой точке); нажатие оставляет её открытой. Нажатие на группу приближает кадр. Наведение на карточку подсвечивает метки этого тренера, наведение на метку — карточку в списке. На ширине от 960px карта слева, карточки справа по три в ряд. Уже этого карта стоит над списком: одна колонка до 720px и три колонки шире. Порядок страницы — расстояние до центра кадра. Если координаты посетителя не пришли или страна не Беларусь, карта открывается от центра Минска и больше сама не сдвигается. Кнопка «Моё местоположение» вызывает Geolocation API и не ходит во внешний геокодер. Точка вне Беларуси карту не сдвигает. Посетителю об этом ничего не пишется: отказ браузера и точка вне страны уходят отдельной строкой `map.locate` в тот же журнал `app_logs`, что и сообщения. Координаты в строку не попадают. У вошедшего строка видна на вкладке «Логи» его аккаунта. Несколько тренеров в одной точке делят метку. Если скрипт карты не загрузился, на месте карты остаётся список уже полученной страницы. Без сети тайлы не приходят, новый кадр не загружается, уже показанные метки и карточки остаются.

В кабинете сотрудника у каждого места бейдж статуса и общая кнопка «Перегеокодировать». Она игнорирует срок кеша. Точку на карте руками не ставят.

Если объём вырастет и публичный Nominatim перестанет подходить, запасной путь — свой Photon (геокодер на данных OpenStreetMap) за тем же серверным интерфейсом. Ключи Яндекса и Google не используются.

### 4.8 Журнал действий

Контракт для агентов: [.cursor/rules/logging.mdc](../.cursor/rules/logging.mdc), навык [.cursor/skills/trenio-logging/SKILL.md](../.cursor/skills/trenio-logging/SKILL.md). Диагностика — команда `/diagnosis`.

Одна таблица `app_logs`. Строка живёт 30 дней (`expires_at`), затем удаляется процессом не чаще раза в час или командой `npm run logs:purge`. Таблицу создаёт `npm run logs:install`. `db:push` для неё не использовать: живой enum `otp_purpose` не совпадает с Drizzle.

Пишется домен и действие (`auth.login`, `email.send`, `form.review`, `map.area`, `message.send`, `ajax.http`, `system.unhandled` и остальные из навыка), итог (`success`, `failure`, `denied`, `skipped`), короткое сообщение, почта или маска телефона, id аккаунта, цель (slug или id переписки), маршрут, код ошибки и обрезанный stack. IP берётся только из `X-Real-IP`.

В журнал не попадают пароль, токен сессии, ссылка сброса, код из SMS или письма, `initData`, cookie и HTML переписки. Текст письма в консоль разработки по-прежнему пишет `AUTH_DEV_LOG_EMAILS`, в базу уходит только факт и тема. Опрос списка и непрочитанного пишется только при сбое. Браузер сообщает свои ошибки и ответы 500 через `reportClientLogsFn`, не больше 20 событий за 5 минут с одного IP.

Вкладки «Логи» на `/admin/accounts/$id` и `/admin/trainers/$slug` смешивают этот журнал с прежней историей из сессий, токенов и отзывов. Stack и context в кабинете не показываются. Порог записи — `LOG_LEVEL`, по умолчанию `info`.

## 7. Mobile-first — обязательное требование

**Mobile-first:** дизайн и реализация начинаются с viewport ≤768px, затем расширяются.

### 7.1 Breakpoint

- Mobile: `< 768px` (`useIsMobile`, Tailwind `md:` = 768px)
- Touch targets: min **44×44px** для интерактива
- Auth forms: single column on mobile (`auth-styles.tsx` media queries)

### 7.2 Чеклист для UI-изменений

| #   | Проверка                                                         |
| --- | ---------------------------------------------------------------- |
| 1   | Layout не ломается на 320px width                                |
| 2   | Нет horizontal scroll на mobile (кроме intentional carousels)    |
| 3   | Header/burger/mega menu работают на touch                        |
| 4   | Forms usable с виртуальной клавиатурой                           |
| 5   | Font size ≥14px для body, контраст WCAG AA                       |
| 6   | Sticky/fixed elements не перекрывают контент                     |
| 7   | `@media (max-width: …)` или Tailwind mobile-first (`sm:`, `md:`) |
| 8   | Desktop-only features имеют mobile alternative                   |

### 7.3 Компоненты

- `SiteHeader` — responsive nav, login icon
- `AuthStyles` — mobile grid collapse
- shadcn `Sheet` / `Drawer` — предпочтительны для mobile overlays
- Карточки каталога — stack on mobile, grid on desktop

### 7.4 Единая layout-сетка

Обязательное правило для всех экранов: `.cursor/rules/layout-grid.mdc`. Глобальные токены и утилиты в `src/styles.css`:

| Token / class | Значение |
| --- | --- |
| `--layout-max` | `1240px` — ширина контента (header, footer, каталог, кабинет тренера и пользователя) |
| `--layout-staff-max` | `1680px` — кабинет `/admin` (роли admin и superadmin). Класс `.layout-staff` подменяет `--layout-max`, шапка и подвал на этих страницах стоят на той же кромке |
| `--layout-prose-max` | `760px` — узкий текст (about, privacy, offer, contacts) |
| `--layout-gutter` | `clamp(20px, 4vw, 36px)` — горизонтальные отступы |
| `--layout-section-y` | вертикальные отступы секций |
| `--layout-sidebar-w` | `280px` — колонка фильтров |
| `.layout-container` | центрированный контейнер с gutter |
| `.layout-with-sidebar` | фильтры 280px + контент, один контейнер с шапкой |
| `.card-grid`, `.clubs-grid`, `.categories-grid`, `.trainer-grid`, `.cat-grid`, `.favorites-grid` | каталог, клубы, категории и избранное: 4 колонки, с 960px — 2, с 640px — 1 |
| `.city-grid`, `.sr-grid`, `.card-grid--4` | города, поиск и широкие ряды: 4 колонки, с 960px — 2, с 640px — 1 |
| `.section-head`, `.section-title` | заголовки секций, размер `--fs-section`, вес `--fw-heading` |

Контейнер один: фон на всю ширину, содержимое `max-width: var(--layout-max)` и `padding-inline: var(--layout-gutter)`. Кабинет администратора и суперадминистратора шире: оболочка `/admin` носит класс `.layout-staff` и читает `--layout-staff-max`. Каталог, `/account` и `/me` остаются на `--layout-max`. Горизонтальный padding не ставится и на внешний блок, и на внутренний сразу. Горизонтальные ленты (иконки, карточки) используют `.layout-rail` и не доходят до края экрана. `--layout-gutter` включает `safe-area-inset`, viewport — `viewport-fit=cover`. Карточки тренеров описаны в `styles.css` и одинаковы на главной, в категориях и в городах.

Типографика тоже в `src/styles.css`. Новые заголовки берут токены, а не `font-weight: 800–900`.

| Token | Значение | Роль |
| --- | --- | --- |
| `--fs-display` | до 48px | герой главной |
| `--fs-page` | до 40px | h1 каталога, города, клубов |
| `--fs-section` | до 26px | h2 секций |
| `--fs-card` | 16px | названия карточек |
| `--fw-heading` | 700 | h1–h2 |
| `--fw-title` | 650 | h3, названия карточек |
| `--fw-ui` | 600 | кнопки, чипы, ссылки |
| `--fw-body` | 450 | текст, базовый размер 15px |
| `--card-radius` | 22px | карточки, панели, баннеры, фильтры, FAQ |
| `--radius-control` | 12px | кнопки, поля, селекты |
| `--radius-tile` | 14px | иконки и логотипы в квадрате |

Чипы и пилюли — `999px`, круги — `50%`. Для интерфейса не использовать `--radius-md` из shadcn: без локального переопределения он даёт около 8px и расходится с карточками.

Breakpoint для collapse sidebar/grid: **`960px`**. Новые страницы используют CSS-переменные, не хардкод `1200`/`1360px`.

## 9. Команды разработки

```bash
nvm use 22
npm install
npm run db:up && npm run db:push && npm run db:seed
npm run geoip:update # база GeoLite2 City в data/geoip
npm run dev          # http://trenio.local (Apache → порт 8080)
npm run build
npm run lint
npm run test         # node:test: журнал, гео, доступ к переписке
npm run test:e2e     # Playwright. Сервер можно не гасить: конфиг его переиспользует
npm run logs:install # таблица app_logs, без db:push
npm run logs:check   # дыры console.error и пробная запись
npm run logs:diagnose -- --level error --hours 24
npm run logs:purge   # строки старше 30 дней
npm run format
```

Локальный хост: `http://trenio.local` (`127.0.0.9` в `/etc/hosts`, Apache → `127.0.0.1:8080`). `APP_ORIGIN` и `APP_URL` в `.env` указывают на этот адрес.

**Seed accounts:** `admin@trenio.by`, `super@trenio.by`, `client@trenio.by` — пароль у всех `Pa55word!`. Клиент — роль `user`, отзывы об Овсянникове, Антипенко и Ахмежанове.
